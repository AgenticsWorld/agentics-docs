# Agent 高级设置

这些设置控制 Agent 怎么运行：同时跑几个、一个任务最长跑多久、不合格的工作重做几次、每个 Agent 记得多少。默认值适合大多数电脑和订阅。遇到瓶颈时再改，例如任务经常超时，或者额度消耗太快。

打开 **⚙️ → 高级 → Agent 高级设置**，修改数值后点 **保存**。所有设置都是全局的（对所有项目生效），作用于保存之后启动的运行；**Debug 模式** 保存后立即生效。点字段旁边的 **i** 可以在对话框里查看说明。

![Agent 高级设置对话框](/images/videoagents/console/agent-advanced-settings.webp)

## 并发 {#concurrency}

| 字段 | 作用 | 范围 | 默认 |
| --- | --- | --- | --- |
| **跨 Agent 并发额度** | 所有 Agent、所有项目加起来最多同时运行几个任务。新任务要等有空槽才能开始。总制片这类调度型 Agent 大部分时间在等子任务，不占槽。它同时是 **单 Agent 并发额度** 的上限。 | 1–50 | 8 |
| **单 Agent 并发额度** | 一个扇出型 Agent 最多同时运行几个任务。扇出型 Agent 按场景或按组工作，例如场景资产、视频生成、审核和评分。创作型 Agent 为了保持对话连续，始终一次只跑一个任务。 | 1–8，不超过跨 Agent 并发额度 | 5 |
| **多集并行** | 关闭：团队一次只做一集，当前这一集的所有步骤（包括它的签字，发布环节除外）都完成后，才开始下一集。开启：第一集走完整条流水线并在签字点 H4 签字之后，后面的各集可以同时推进。 | 开 / 关 | 关 |

每个槽都是一个真实的引擎进程。调高并发会更快消耗额度，加重电脑负载，代理连接也更容易断。请逐步调高。

**多集并行** 关闭时，一集之内的工作仍然并行进行（各组、各镜头、各场景），速度取决于并发额度。如果当前这一集停在签字点，或被暂缓、被阻塞，后面的集不会开始；开着自动运行时，它会提醒你。开启多集并行能提高吞吐量，但 token 消耗、同时运行的进程，以及等你审看的内容也会增加。

## 超时和轮次 {#timeouts-and-turns}

| 字段 | 作用 | 范围 | 默认 |
| --- | --- | --- | --- |
| **运行超时(分钟)** | 单个任务最长运行时间。到时间后，任务和它的子进程会被终止，并记为出错。总制片要等整条流水线，它的时限是这个值的四倍。 | 10–1440 | 120 |
| **无输出超时(分钟)** | 引擎连续多久没有任何输出，就判定任务卡死并终止。它比运行超时更早发现挂起的连接和代理断流。0 表示关闭。总制片不受这项限制。 | 0–360 | 30 |
| **轮次上限** | 引擎在一张工单里最多进行多少轮对话。只有 claude 和 grok 引擎有这个限制，其他引擎会忽略它。 | 10–1000 | 250 |

::: tip 提示
单次工具调用期间，引擎不会有任何输出，所以无输出超时必须比任务里最长的一次工具调用更长，例如一次较长的视频渲染。
:::

撞到轮次上限时，引擎会被直接切断，任务无法续跑；已经写好的文件会保留，但核验和回执会缺失。如果处理几十个组的任务撞到上限，先让派单的批次小一些，再考虑调高这个值。

## 重跑和确认 {#retries-and-confirmations}

| 字段 | 作用 | 范围 | 默认 |
| --- | --- | --- | --- |
| **重跑次数** | Agent 最多可以自行重做几次：评分、审核或机检不过时退回重做，以及重新生成检查不达标的图片和视频。一个任务用完重跑次数仍然不过，就交给你决定。0 = 不自动重跑，第一次不过就交给你。 | 0–10 | 0 |
| **重跑等待确认(秒)** | 重跑类确认卡片（例如 **重跑** / **跳过**）等待多久。倒计时结束后采用默认选项，流水线不会卡住。Agent 可以要求更短的等待，但不能更长。签字卡片从不倒计时。 | 5–3600 | 60 |

**重跑次数** 和 `/retry` 命令是同一个设置。见[聊天命令](/zh/videoagents/console/chat-commands)。

::: warning 注意
每次重跑都会再运行一次 Agent，往往还要再调用一次生成模型。重跑次数越高，可能消耗的引擎额度和生成费用越多。
:::

## 思考和记忆 {#thinking-and-memory}

| 字段 | 作用 | 范围 | 默认 |
| --- | --- | --- | --- |
| **思考深度** | 所有 Agent 的推理深度，会传给各个引擎自己的对应设置。越深越可靠，但越慢、token 消耗越多。**引擎默认** 不传任何参数，沿用各引擎自己的配置。 | 引擎默认、low、medium、high、xhigh、max | 引擎默认 |
| **对话记忆** | 创作型 Agent 对话历史的大小上限，单位 KB。创作型 Agent 每次运行都接续上一次的会话；会话超过这个大小后，自动新开一个会话。0 表示关闭记忆：每次运行都是全新会话，信息只通过项目文件传递。 | 0–256 KB | 16 KB |

**思考深度** 在各引擎中的对应方式：claude 和 antigravity 用 `--effort`；codex 用 `model_reasoning_effort`，grok 用 `--reasoning-effort`（两者都把 **max** 按 xhigh 处理）；pi 和 agentics 用 `--thinking`（本地模型不传）；opencode 用 `--variant`（模型没有对应档位时被忽略）。kimi 引擎没有这项设置。

**对话记忆** 越大，连续性越长，但每一轮都要重发全部历史，速度更慢、token 更多。设为 0 可以明显节省 token。会话 ID 仍会照常保存，所以再调大时会从最近的会话接着继续。滑块下方的一行显示会话续接是否开启。要重置某一个 Agent 的会话，在它的对话里发 `/clear`。

## 白模和 Debug 模式 {#whitebox-and-debug-mode}

| 字段 | 作用 | 默认 |
| --- | --- | --- |
| **白模自检** | 白模调度 Agent 每次新建或修改一个组之后，为每个镜头渲染几张静帧（开头、中间、结尾和一张空间视角），每组拼成一张联系表，在交给你之前检查取景、遮挡、朝向和景别。渲染在本机完成，不收费；每组大约多花十几秒，外加读一张图的 token。关闭后只做数值检查。 | 开 |
| **Debug 模式** | 显示开发者入口，例如每个 Agent 对话标题栏里的 **SOUL.md** 按钮。保存后立即生效，不影响任何运行。 | 关 |

见 [3D 白模预演](/zh/videoagents/create/whitebox-previs)。
